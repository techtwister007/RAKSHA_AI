02

The gap we address

Every cyber-reasoning system today assumes a cloud LLM. A classified network has none.

The deployment wall

Armed-Forces code lives on air-gapped networks. A tool that phones a foreign cloud API is structurally undeployable there — the attack surface is the controlled transfer, not the internet.

The noise wall

AI scanners flood reviewers with findings that carry no proof. The curl project shut its bug-bounty after AI submissions overwhelmed its maintainers. On a military network, wasted review time is scarce cleared manpower.

Our answer

A single sealed node. No network interfaces. A local model proposes; a deterministic verifier decides. Nothing unproven ever reaches a live system.

Judged on: accuracy / precision · speed · least resources · functionality · scalability.

03

The central bet

The LLM is not the brain. The verifier is.

The best frontier agents score ~34% on patching and ~18% on proof-of-concept generation. The documented failures are scaffold problems, not model-size problems. So we compete on the scaffold.

Two invariants, enforced in code — not promised in a slide

  • No reproducer, no report. A finding without a reproducer that actually replays can never be reported. "100% precision on reports" is therefore structural, not tuned.
  • Nothing unproven ships. A patch is VERIFIED only when all five mechanical checks pass on the patched build. Else it is a proven report for a human — never a guess.

Both raise InvariantViolation in raksha/finding.py. The model cannot overrule them.

04

How it works — one pipeline, three acts

Find → Fix → Prove

FIND   build + instrument → install sink oracles → fuzz / static / taint / structural
FIX    dedup & localise (the sanitizer gives the line) → repair ladder, cheapest first
PROVE  five-check gate → signed evidence bundle → learn (vaccine, memory)

The five-check gate — a patch earns all five, every round

1 COMPILES · the patched build builds

2 POV DEAD · the exploit no longer fires

3 DIFFERENTIAL · corpus output + own tests unchanged (+ perf)

4 COVERAGE HELD · the fix site is still reached (no delete-to-fix)

5 CLEAN REFUZZ · the reproducer's whole neighbourhood stays dead

+ RED TEAM · an independent attacker re-tries to break it

Check 5 opens with 24 deterministic variants of the reproducer: the shallow fix that silences one input dies here.

05

The key novelty

Model what the system must never do — then make the machine try to do it.

Non-crashing vulnerabilities — command injection, auth bypass, weak crypto — get a runtime invariant injected at the sink, so they abort exactly like a memory bug.

untrusted input → … → command execution  ❌ aborts at the sink → reproducer → patch → re-prove

One verification architecture covers every bug class, instead of a fuzzer for memory bugs and a separate AI scanner for everything else.

Shipped as sink oracles: AddressSanitizer (C/C++), Jazzer (Java), a Python sink guard, Go panics, a ThreadSanitizer race oracle, a Node sink guard.

08

Honesty is the product

It never says "secure". It says what it proved, and what it did not analyse.

Assurance boundary

Every run reports languages exercised by exploit vs build-free only, targets that would not build, suspected-but-unproven findings, and dependencies the code never imports. Presence, never absence.

Evidence a judge can run

A shell-safe replay.sh, the reproducer bytes, and an HMAC-signed bundle that names the environment the proof was made in and detects a single changed byte.

Fail-closed by design

If no patch survives all five gates, no patch is issued — only a verified vulnerability report, flagged for a cleared human under the Rules of Engagement in force for that asset.

A dependency CVE in a library the code never imports is ranked down, not dressed up as an exploit.
