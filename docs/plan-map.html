The whole idea in one picture

Why this shape. The best AI models in the world fail this task about two times in three, and none can run on a sealed Army network anyway. So instead of hoping for a smarter model, we make the model irrelevant to the question of truth: a weak model guesses, a mechanical inspector decides. A weak guesser is fine when the judge cannot be fooled. If nothing proves out, the system says so instead of guessing.

Vet thisDo you agree the product is "the inspector plus the receipts", and the model is a replaceable part inside it? Everything else follows from this.

The single most important strategic decision: two tracks

Why it matters. The raw odds of a flawless live run on an unknown target are about 36% (build works × bug found × patch validates). That number was for letting the pitch depend on the unknown. We don't. The demo is certain because we own it; the evaluation is honest because we don't pretend. Said aloud: "Here is a bug we know, fixed in front of you. And here is what the same system found on the target you gave us four hours ago."

Vet thisAre you comfortable that the headline demo is on a known bug (CVE-2021-44228, log4j 2.14.1), openly stated as a controlled demonstration, with the unknown-target result shown beside it?
4

The machine, in six steps

The two exits are the point. A system this ambitious will fail somewhere on an unknown target. Ours narrows instead of stopping: a target that will not even build still produces verified findings within minutes (outdated libraries, leaked secrets, misconfiguration), and a bug with no validated fix still produces a signed, proven report. Every exit is a real result, never a blank screen.

Vet thisSix steps, two safe exits, one sandbox. Is anything you expected the system to do missing from this picture?

What gets built, in what order, and what proves each step is done

The principle. Make the core flawless, make a few wow beats perfect, describe the rest. The order is impact-per-effort: the keystone first because everything consumes it; the console early because it is the scoring interface; the vaccine last because it is the hardest to fake and the first to cut.

8

If it breaks — the ladder down, and every rung is still a result

1Their target won't build → static, dependency, secret and config lanes keep going. Findings in minutes. Board shows amber: still finding.
2Target is in a language we never adapted (Go, Rust, C#) → the dependency and secrets lanes work on anything. Still real findings.
3Can't generate a fuzz harness → Java never needed one (Jazzer writes it); C uses a hand-written one, said openly.
4Fuzzing finds nothing in time → the other lanes were running in parallel the whole time, not after.
5No fix passes the inspector → a signed, proven vulnerability report. Scored, honest, no patch claimed.
6No GPU, or the model server dies → smaller model → CPU only → templates and lookup only. The inspector never needed a model.
7Our whole pipeline stalls → an independent open-source CRS runs in parallel on the same target.
8The live demo dies → the full run was recorded at a safe point; narrate over it. Almost nothing lost.
9A judge challenges a number → every number comes from our own benchmark run, losses shown beside wins. Nothing borrowed.
10A judge holds up the old deck ("two 8B models, ≥ 90%") → the reconciliation sentence, said in the first minute before anyone asks.

The honest arithmetic. Without this ladder: ~36% for a flawless live run. With it: ~85–90% for a convincing demo of something real — and the demo track (block 3) takes that to ≈95%+. Our confidence comes from degrading instead of dying, not from assuming nothing fails.

Vet thisIs there a failure you can imagine that isn't on this ladder? That is the one to add.

Eleven things we must find out from the organisers before building more

The plan silently assumed answers to all of these. Two are existential. Ask in writing now; where they stay silent, we build to the stated assumption and say so in the room.

Q1 · Is pre-built code allowed?If only the 36 hours count, the order flips. Assume: allowed.
Q2 · Scored by a machine or by the jury?If a machine, a wrong submission format scores zero. Assume: both; build a swappable exporter.
Q3 · Source repos, containers, or live hosts?Live hosts favour black-box lanes and honest reports. Assume: mixed.
Q4 · Do proven-but-unpatched reports score?Decides breadth vs depth. Assume: patches score more → dependency bumps first.
Q5 · Our hardware or theirs? GPU?Assume: ours allowed; carry GPU and CPU bundles.
Q6 · Any language hint?Assume: none; Java deepest.
Q7 · Team size at the finale?Assume: two; recruit one teammate for the 36 hours.
Q8 · May we fuzz their targets at full rate?Crashing a shared defence test environment is a disqualification. Assume: rate-limit, kill handle.
Q9 · Judging format — minutes, judges, technical or military?Assume: 7 min + questions, mixed jury.
Q10 · Will the jury have read the shortlisting deck?Assume: yes; reconciliation line ready.
Q11 · Does their code stay on our machine? Wipe afterwards?Assume: yes and yes; wipe script ready.
